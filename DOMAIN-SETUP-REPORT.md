## C. DNS в REG.RU

В зоне **tm-cert.ru** создать:

| Тип | Имя / поддомен | Значение |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | moiseenkova1987-source.github.io |

TTL можно оставить стандартный, например 3600 секунд. В значение CNAME не добавлять HTTPS, путь репозитория или завершающий `/`.

Редактировать нужно зону на фактически обслуживающих домен DNS-серверах. Если домен ещё не делегирован, сначала проверить его статус и назначение DNS-серверов в REG.RU. Не менять NS вслепую, если зона уже используется для почты или других сервисов.

Перед добавлением проверить старые записи парковки/переадресации: посторонние A/AAAA для корня и записи на имени www могут конфликтовать. Для www не оставлять A/AAAA или второй CNAME одновременно с указанным CNAME. MX/TXT почты и другие независимые записи сохранять. IPv6 для этой минимальной схемы не обязателен; посторонние AAAA не должны направлять посетителей на другой хост. Если есть ограничивающие CAA, проверить возможность выпуска сертификата GitHub Pages.

IP-адреса и CNAME сверены с [официальной документацией GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## D. Ручные действия в GitHub

После согласования переключения:

1. Открыть [Settings → Pages](https://github.com/moiseenkova1987-source/tatyana-moss-certification/settings/pages). Source оставить **GitHub Actions**.
2. В **Custom domain** ввести `tm-cert.ru`, без протокола и пути; нажать Save. Сохранить привязку до направления DNS на GitHub.
3. Внести DNS-записи в REG.RU. Согласовать по времени привязку домена и push новой сборки: до завершения обоих действий возможен временный период некорректных ссылок или недоступности.
4. По отдельному разрешению выполнить commit/push подготовленных изменений, дождаться успешного Pages workflow.
5. После успешной DNS-проверки и выпуска сертификата включить **Enforce HTTPS**. Выпуск/доступность этой настройки могут потребовать до 24 часов; фактический статус проверить в Pages.
6. Проверить HTTPS для обоих адресов. При основной привязке `tm-cert.ru` вариант `www.tm-cert.ru` должен перенаправлять на основной домен. Проверить вложенные страницы, фото, CSS, favicon и сохранение noindex.

Итоговые HTTPS и redirect нельзя подтвердить локальной сборкой: они зависят от DNS, привязки Pages и выпуска сертификата. Сейчас эти действия не выполнены.
